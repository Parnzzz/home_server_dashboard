ส่วนประกอบของ Backend

เอกสารนี้อธิบายหน้าที่และความรับผิดชอบของส่วนประกอบต่าง ๆ ภายใน Backend เพื่อให้เข้าใจบทบาทของแต่ละส่วนและสามารถพัฒนาระบบได้อย่างเป็นมาตรฐาน

1. Model

หน้าที่: กำหนดโครงสร้างข้อมูลของระบบ

กำหนดฟิลด์และชนิดข้อมูล

กำหนดโครงสร้างข้อมูลที่ใช้ภายในระบบ

กำหนดความสัมพันธ์ของข้อมูล

ใช้เป็นตัวแทนข้อมูลจากฐานข้อมูล

2. DTO (Data Transfer Object)

หน้าที่: กำหนดรูปแบบข้อมูลสำหรับรับส่งระหว่างส่วนต่าง ๆ ของระบบ

กำหนดโครงสร้างข้อมูลสำหรับ Request

กำหนดโครงสร้างข้อมูลสำหรับ Response

ควบคุมข้อมูลที่อนุญาตให้รับหรือส่ง

แยกรูปแบบข้อมูล API ออกจาก Model ภายในระบบ

3. Middleware

หน้าที่: ตรวจสอบและประมวลผลคำขอก่อนส่งต่อไปยัง Handler

ตรวจสอบสิทธิ์การเข้าถึง (Authentication)

ตรวจสอบสิทธิ์การใช้งาน (Authorization)

บันทึกข้อมูลการเรียกใช้งาน (Logging)

จัดการข้อผิดพลาดที่เกิดขึ้นระหว่างการประมวลผล

กำหนดมาตรการรักษาความปลอดภัยของ API

4. Config

หน้าที่: จัดการการตั้งค่าของระบบ

อ่านค่าจาก Environment Variables

กำหนดค่าการเชื่อมต่อ Database

กำหนดค่า Port ของ HTTP Server

จัดการค่าการตั้งค่าตาม Environment

รวมศูนย์การตั้งค่าเพื่อให้ส่วนต่าง ๆ เรียกใช้งานร่วมกัน

5. Router

หน้าที่: กำหนดเส้นทางและเชื่อมโยง HTTP Request ไปยัง Handler

กำหนด API Endpoints

กำหนด HTTP Methods

เชื่อมโยงเส้นทางกับ Handler

กำหนด Middleware ให้กับแต่ละเส้นทาง

จัดกลุ่มเส้นทางตามทรัพยากรหรือประเภทการใช้งาน

6. Database

หน้าที่: จัดการการเชื่อมต่อและการทำงานร่วมกับฐานข้อมูล

สร้างการเชื่อมต่อฐานข้อมูล

จัดการ Connection Pool

ตรวจสอบสถานะการเชื่อมต่อ

จัดการวงจรชีวิตของ Database Connection

7. Logger

หน้าที่: บันทึกเหตุการณ์และข้อมูลการทำงานของระบบ

บันทึกข้อมูลการทำงานของระบบ

บันทึกข้อผิดพลาด

บันทึกเหตุการณ์สำคัญ

ช่วยตรวจสอบและวิเคราะห์ปัญหา

หลักการออกแบบ

ส่วนประกอบแต่ละส่วนควรมีหน้าที่ชัดเจน ไม่รับผิดชอบงานที่อยู่นอกเหนือขอบเขตของตนเอง และควรลดการพึ่งพากันโดยไม่จำเป็น เพื่อให้ง่ายต่อการทดสอบและบำรุงรักษา
