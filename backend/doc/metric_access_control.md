การควบคุมสิทธิ์การเข้าถึงข้อมูล Metrics

ภาพรวม

ระบบต้องควบคุมการเข้าถึงข้อมูล Metrics เพื่อให้ผู้ใช้สามารถดูข้อมูลการตรวจสอบสถานะ (Monitoring) ได้เฉพาะ Server ที่ตนเองเป็นเจ้าของเท่านั้น

การตรวจสอบสิทธิ์ต้องดำเนินการในฝั่ง Backend เพื่อป้องกันไม่ให้ผู้ใช้เข้าถึงข้อมูลของผู้อื่นผ่านการเปลี่ยน Server ID ใน API Request

1. วัตถุประสงค์

จำกัดการเข้าถึงข้อมูลตามเจ้าของ Server

ป้องกันการเข้าถึงข้อมูลข้ามบัญชีผู้ใช้

ป้องกันการเข้าถึงข้อมูลโดยไม่ได้รับอนุญาต

รักษาความเป็นส่วนตัวและความปลอดภัยของข้อมูล Metrics

2. หลักการทำงาน

เมื่อผู้ใช้เรียก API เพื่อดูข้อมูล Metrics ระบบจะดำเนินการดังนี้

ตรวจสอบตัวตนของผู้ใช้จาก Access Token

ระบุ User ID จากข้อมูลการยืนยันตัวตน

ตรวจสอบว่า Server ที่ร้องขอเป็นของผู้ใช้รายนั้นหรือไม่

หากเป็นเจ้าของ Server จึงอนุญาตให้เรียกดูข้อมูล Metrics

หากไม่ใช่เจ้าของ Server ให้ปฏิเสธคำขอ

3. ลำดับการตรวจสอบสิทธิ์

Client → Handler → Service → Repository → Database

การตรวจสอบสิทธิ์ความเป็นเจ้าของ Server ควรดำเนินการใน Service และใช้ Repository ตรวจสอบความสัมพันธ์ระหว่าง User กับ Server ก่อนอนุญาตให้เข้าถึง Metrics

5. แนวทางด้านความปลอดภัย

ตรวจสอบ Access Token ทุกครั้งที่เรียก API ที่ต้องยืนยันตัวตน

ไม่เชื่อถือ User ID ที่ส่งมาจาก Client โดยตรง

ใช้ User ID จากข้อมูลที่ผ่านการยืนยันตัวตนแล้ว

ตรวจสอบความเป็นเจ้าของ Server ก่อนเรียกดู Metrics

ไม่เปิดเผยข้อมูลของผู้ใช้งานรายอื่นใน Response

6. ผลลัพธ์ที่คาดหวัง

ผู้ใช้งานแต่ละรายสามารถเข้าถึงข้อมูล Metrics ได้เฉพาะ Server ที่ตนเองเป็นเจ้าของ ช่วยป้องกันการเข้าถึงข้อมูลข้ามบัญชีและเพิ่มความปลอดภัยให้กับระบบ
